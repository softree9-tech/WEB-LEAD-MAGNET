## 2025-05-14 - SSRF Protection with IP Validation
**Vulnerability:** Server-Side Request Forgery (SSRF) via user-provided URLs in website analysis and lead processing endpoints.
**Learning:** Standard URL validation that only checks for the presence of a protocol or basic hostname patterns is insufficient. Attackers can use decimal IP representations, custom hostnames pointing to internal IPs, or IPv6 loopback addresses to bypass simple blacklists. Standard `socket.gethostbyname` resolution is insufficient as it often misses IPv6 addresses or hostnames that resolve to both public and private IPs.
**Prevention:** Use `socket.getaddrinfo` to resolve *all* potential IP addresses for a hostname and validate every one of them against private, loopback, and reserved ranges (RFC 1918, RFC 4193). Note: Validation followed by a separate request is still technically vulnerable to DNS rebinding (TOCTOU) unless the resolved IP is pinned for the actual HTTP request.
